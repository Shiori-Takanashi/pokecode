# GitHub Actions で Flask サーバーをテストする方法

GitHub Actions で Flask サーバーを起動してテストを実行することは可能です。このドキュメントでは、2つの実装方法を紹介します。

## 方法1: GitHub Actions で直接起動する方法

Flask サーバーをバックグラウンドで起動し、テストを実行する方法です。

### 実装例

```yaml
# filepath: .github/workflows/ci.yml
name: CI

on:
  push:
    branches: [version01, version02, version03]

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python-version: ["3.14"]

    steps:
      - uses: actions/checkout@v4

      - name: Install uv
        uses: astral-sh/setup-uv@v4
        with:
          version: latest

      - name: Set up Python
        run: uv python install ${{ matrix.python-version }}

      - name: Install dependencies
        run: uv sync --dev

      - name: Start Flask server in background
        run: |
          uv run python server/app.py &
          echo $! > flask.pid
          sleep 5  # サーバー起動を待つ

      - name: Check Flask server health
        run: |
          curl --retry 5 --retry-delay 2 --retry-connrefused http://127.0.0.1:5000
          curl --retry 5 --retry-delay 2 --retry-connrefused http://127.0.0.1:5000/json

      - name: Run tests (pytest)
        run: uv run pytest --verbose --tb=short

      - name: Stop Flask server
        if: always()
        run: |
          if [ -f flask.pid ]; then
            kill $(cat flask.pid) || true
          fi

      - name: Lint and format (ruff)
        run: |
          uv run ruff check .
          uv run ruff format --check .

  build:
    runs-on: ubuntu-latest
    needs: test
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v4
        with:
          version: latest
      - run: uv python install 3.14
      - run: uv build
      - uses: actions/upload-artifact@v4
        with:
          name: dist
          path: dist/
```

### メリット

- シンプルな実装
- CI 環境で実サーバーの動作確認が可能

### デメリット

- テスト失敗時にサーバープロセスが残る可能性がある
- デバッグが難しい

## 方法2: pytest fixture で管理する方法（推奨）

pytest の fixture として Flask サーバーを管理する方法です。テストの前後で確実にサーバーの起動・停止を制御できます。

### conftest.py の実装

```python
# filepath: tests/conftest.py
import logging
import pytest
import subprocess
import time
import requests
from pathlib import Path


def _reset_all_loggers():
    """すべてのロガーとハンドラーをリセット"""
    for logger_name in list(logging.Logger.manager.loggerDict.keys()):
        logger = logging.getLogger(logger_name)
        for h in logger.handlers[:]:
            logger.removeHandler(h)
        logger.setLevel(logging.NOTSET)
        logger.propagate = True

    root = logging.getLogger()
    for h in root.handlers[:]:
        root.removeHandler(h)
    root.setLevel(logging.NOTSET)
    root.propagate = True


@pytest.fixture
def reset_logging():
    _reset_all_loggers()
    yield
    _reset_all_loggers()


@pytest.fixture(scope="session")
def flask_server():
    """Flask サーバーをテストセッション中起動"""
    server_script = Path(__file__).parent.parent / "server" / "app.py"

    # Flask サーバーをバックグラウンド起動
    process = subprocess.Popen(
        ["python", str(server_script)],
        stdout=subprocess.PIPE,
        stderr=subprocess.PIPE,
    )

    # サーバー起動を待つ
    max_retries = 10
    for _ in range(max_retries):
        try:
            response = requests.get("http://127.0.0.1:5000", timeout=1)
            if response.status_code == 200:
                break
        except requests.RequestException:
            time.sleep(1)
    else:
        process.kill()
        raise RuntimeError("Flask server failed to start")

    yield "http://127.0.0.1:5000"

    # テスト終了後にサーバーを停止
    process.terminate()
    process.wait(timeout=5)
```

### テストコードの実装例

```python
# filepath: tests/test_integration.py
import pytest
from pokecode.request_html import request_html
from pokecode.request_json import request_json


@pytest.mark.usefixtures("flask_server")
def test_request_html_with_flask(flask_server):
    """Flask サーバーから HTML を取得"""
    html = request_html(flask_server)
    assert len(html) > 0
    assert "<!DOCTYPE html>" in html


@pytest.mark.usefixtures("flask_server")
def test_request_json_with_flask(flask_server):
    """Flask サーバーから JSON を取得"""
    data = request_json(f"{flask_server}/json")
    assert isinstance(data, dict)
    assert "MSG" in data
```

### メリット

- テスト後に確実にクリーンアップされる
- ローカルでも CI でも同じテストを実行可能
- サーバー起動の失敗を検出しやすい
- デバッグがしやすい

### デメリット

- 実装がやや複雑

## 推奨事項

現在のプロジェクト構成では、**方法2: pytest fixture で管理する方法を推奨**します。

理由：
- テストの信頼性が高い
- ローカル開発環境でも同じテストを実行できる
- サーバープロセスの管理が確実

## 必要な依存パッケージ

pytest fixture を使う場合、`requests` パッケージが必要です。

```bash
uv add --dev requests
```
